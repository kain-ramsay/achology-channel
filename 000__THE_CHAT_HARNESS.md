# THE CHAT HARNESS

**Version 1.10, S309. Authority: Kain Ramsay.**

Version 1.10 tightens Open Step 1 to count both sides of the road, ruled by
Kain at S309 after Chat found 42 files in FROM Chat, from S245 to S308, that
Code had never archived. Code's Rule 13 already required him to archive them
at every close; the rule stood and nothing enforced it, and Chat's open only
ever counted its own inbox, so the pile was invisible from both ends for
thirty sessions. **Open Step 1 now also counts FROM Chat and names the
oldest file in it that carries no head line**, so a skipped Code close is
seen by a different mind within one session, which is what Layer 3 is for.
The matching machine check on Code's side is a hook he builds under a BRIEF
sent S309. **The test, set by date so it fires without memory: at the S315
open, no file in either inbox is older than one session of its reader
without a head line, and every OWED BACK line has its readback.** If the pile
is back, the design was wrong and the cause is reopened, never a fifth layer
added. No rule is added and none leaves; an existing mechanism is tightened,
per Rule 8.

Version 1.8 answers the question Kain carried into S267 and did not accept an
answer to at S266: can this mechanism guarantee that Code's work reaches the
record and the Notion board stays current. The honest answer given at S267 is
no, and the version closes the two places a fresh reading found it breaking.

**First, the proof of a disposition moves from the message to the file.** V1.7
put a disposition beside every inbox file in the opening message, which is the
right check in the right place, but its evidence lives in a chat message that
disappears the moment the session ends. So the count and the disposition line
alone could both be truthful and the work still not done, which is what
happened at S266 and what happened again in the first turn of S267: the report
was read first, correctly, and the board was not moved. **Before any TO Chat
file is archived, one line is written at the head of that file saying what was
done with it and which board cards moved. A file that stays in the inbox
carries one line naming the single fact it waits on.** The folder becomes the
record instead of the message, and the next session's evaluator grades the
previous one by reading the folder rather than believing a number.

**Second, the open's channel check becomes a comparison rather than a self
report.** The bare count "N files read" is retired as proof: it never caught
anything, because ten files read and one actioned still counts as ten files
read. In its place, one comparison a different mind runs at every open: the
date of the newest session report in the channel against the date of the newest
deployed theme version. Theme moved, no report after it, work is owed, and it
is named to Kain in the opening line. This catches a missing report without
either side being honest about it.

No rule is added. One obligation is retired (the count as proof) and two
existing mechanisms are tightened, which is the direction Rule 8 requires.

Version 1.7 tightens Open Step 1, ruled by Kain at S266 after Chat read ten channel files, gave him a summary of them, and dispositioned one. Standing rule 18 has forbidden read-and-parked since S224 and the close counts the inbox at Step 5, but both check at the session's edges: the close fires hours after the failure, and it is Chat checking its own work. So the failure was invisible until Kain found it himself, twice in one session, which is the exact thing this harness exists to stop him having to do. **Open Step 1 now prints a disposition beside every file in TO Chat, not a list of names:** for each file, one line saying what happens to it this session, or that it stays and the one named fact it waits on. A file Chat intends to skip becomes visible to Kain in the opening message rather than at the close, or never. No rule is added and none leaves; a mechanism that already existed is moved to where the failure happens, which is the closure Rule 8 prefers. Kain's words, S266: "I honestly wish there was something we could put in place that would allow me to no longer have to keep on asking to do this."

Version 1.6 adds one Layer 2 mechanism, the output gate, ruled by Kain at S264 when he asked whether Code's strengthen-the-machinery principle should apply to Chat: obligations Chat currently honours by eye (the banned dash characters, banned vocabulary, UK spelling) are mechanised where the environment allows, by running produced text through a script in Chat's own code environment before it travels to a file or to Kain, with the script's count as the printed artefact. This mechanises obligations that already exist (the S222 dash ban and the qc_gate checks); no rule is added, none leaves, and Rule 8 is untouched, because strengthening a mechanism is the closure the governor prefers. The honest limit is stated where Layer 2 already states it: nothing can intercept Chat from outside, so the gate binds only when run, and the next session's evaluator remains the catch behind it.

Version 1.5 corrects Rule 3's register sentence: a DSRD write no longer updates the change register in the same turn; the register is written once at session close, one row per DSRD covering the session's edits. The per-edit write had Chat rewriting the register's largest row after every small ruling, which was the largest single context cost and was forcing mid-session compaction. A correction to an existing rule, one obligation retired, no rule added, per Rule 8.

Version 1.4 closes the contradiction between Rule 8 and this document's own CHANGES section, which instructed the exact one-way growth Rule 8 exists to stop. It removes the three surviving references to the DID line, retired at S253 but still named in Layer 2 as a live mechanism and in Layer 3 as Kain's check. Rule 8 gains its third entry condition, that a rule carries a test. The pass removes four things and adds one, which is the direction Rule 8 requires.

Version 1.3 removes the Rule 8 written earlier the same session and replaces it with the growth governor, after Kain traced the real fault: the operating system had grown one-way for 252 sessions, satisfying its obligations had become the work, and adding rules in response was making it worse. Version 1.2 added the removed rule. Version 1.1 adds Rule 7, no future tense. Version 1 was designed with Kain at S244 and delivered whole in that session.

## Purpose

**This harness reconciles the whole project delivery system.** Ruled by Kain,
S244. Claude Code has a harness governing how he builds. Claude Cowork has a
harness governing how it produces. Claude Chat governs both, and until this
document it ran on rules with no mechanism: every standard in the project was
enforced by Chat remembering to enforce it, and when Chat forgot, nothing
caught it except Kain, which is exactly what the operating system exists to
prevent.

Every failure this harness is designed against is evidenced, not imagined:
two copies of one truth drifting apart with nothing assigned to compare them.
Spec against build (six button paddings from one missing DSRD line). State of
work against reality (a handover claiming 14 inbox files when there were 20).
Decisions against their transport (rulings queued unread in a folder across
sessions). Rules against enforcement (a close that ran differently every
session because its clipping was invisible). Intention against execution
(three stated actions in one session that never happened). This harness makes
the comparisons mechanical and their results printed.

It has three layers, per the vault methodology `A Harness Has Three Layers -
Rules, Mechanisms, And An Independent Evaluator`.

## LAYER 1: THE RULES

### Rule 1. Open by the ritual, close by the ritual
Every session opens with the five-step open and closes with the nine-step
close. The steps live in one place, the `session-close` skill, which replaced
the retired session-closing and session-handover skills at S244. No lighter
version of either ritual exists. The Notion Session Journal is cut (ruled
S244): the handover is the close's one written record.

### Rule 2. A decision is written home in the turn it is settled
Never held for the close. The close's decision sweep is the backstop, not the
mechanism: the mechanism is the turn itself. This is what protects a session
that dies mid-way: a compacted or abandoned session loses minutes of
unwritten work, not hours, because nothing settled is ever waiting.

### Rule 3. Every write is verified by read-back
No edit is reported done from intention. The file is read back, or the
returned diff accepted, before the report. The DSRD change register is
written once, at session close, as one row per DSRD covering the session's
edits (S256, retiring the per-edit register write).

### Rule 4. A stated fact names a source read this turn
Anything asserted as true, current, or done was read from the file, board, or
folder that holds it, in this turn. A claim from memory of an earlier session
is flagged as unverified or not made.

### Rule 5. Kain's rulings reach the record by one named route
Kain rules wherever he is working: Chat, a Code session, a Cowork session.
When a ruling arrives from a Code or Cowork session (as a RULING file in TO
Chat, under their harness rules), Chat writes it into the owning document in
the session that reads it, then archives the file. A ruling of Kain's that
is live in a build but absent from its owning document is a harness break.

### Rule 6. The two status lines are mandatory
The OPEN line ends the first message of every session; the CLOSE line ends
the last. A session missing either line is a broken session. The lines and
their exact shapes are in the `session-close` skill.

### Rule 7. No future tense. Every turn ends done or asking.
**Added S253, on Kain's finding.**

An action named in a message is executed in that message, before it is sent.
There is no third state: a turn either carries out the work and reports it,
or asks Kain the one question that unblocks it. Nothing is left standing as
an intention.

**Banned outright, in every message:** "I will", "I am now going to", "next
I'll", "let me go and", "moving to X now", and every other construction that
describes work in the future tense. If the sentence would be true only after
the message is sent, the work is done first and the sentence is rewritten in
the past tense.

**Why this is a mechanism and not an attitude.** Chat's turn ends the moment
it stops writing. A stated intention costs nothing to produce and feels like
completion from the inside, while reading to Kain as a commitment. Code
cannot fail this way: hook H5, the completion gate, physically blocks him
from ending a turn without his gate printouts. Chat has no hooks, which this
document's Layer 2 states plainly, so the identical failure is impossible on
one side of the channel and unguarded on the other. Rule 7 closes that gap
with the only instrument Chat has, a printed artefact.

**The DID line.** Retired at S253 by Rule 8 part 2, as a mandatory field
governing message shape. What survives is the substance: a change is
reported only after it has been made and verified, never as an intention.

**Two things Rule 7 does not do.** It does not force large work into one
turn: work genuinely spanning several turns reports what was completed in
each. And it does not license silence: a turn that hits a real blocker says
so and asks, which is the second permitted ending.

### Rule 8. The system may not grow one-way. Nothing may govern the shape of a message.
**Added S253, replacing the Rule 8 of v1.2, which was removed the same session it was written.**

**The ratchet, named.** Every harness in this project says the same thing in
its closing section: every failure discovered in use is closed by a new
versioned rule. Nothing anywhere says a rule is ever removed. Across 252
sessions that produced a one-way accumulation: three harnesses, fifty-odd
skills, twenty-four standing rules, eighteen named failure types in one
skill alone, and a success-test gate at the foot of every skill file. The
accumulation was never audited because each addition was individually
correct.

**What it did.** Satisfying the obligations became the work. A report is the
artefact a gate produces, so an output optimised for proving compliance
turns into a report, every time, regardless of what was asked. Kain named
the symptom at S253: message after message of information dropped on him to
interpret, in a collaboration that had been proactive for 252 sessions. The
v1.2 Rule 8 was written in response and made it worse, because it added
another mandatory field to every message. The cure was the disease.

**The two-part governor:**

1. **A rule enters only as another leaves.** Any new rule in this harness,
   The Harness, the Cowork harness, the Project Instructions' standing
   rules, or any skill, names the rule it replaces or the obligation it
   retires. A version that only adds is refused. Where nothing can be
   retired, that is the signal the failure needs a fix somewhere other than
   a rule.

2. **No rule governs the shape of a message.** Rules govern the conduct of
   the work: what gets read before deciding, what gets verified before
   claiming, what gets written before a session ends. A rule prescribing
   what every message must contain, a fixed finding shape, a mandatory
   closing decision, a required line at the foot, is banned, and any that
   exist are removed on sight. Message shape is judgement, exercised fresh
   each time against who is reading it and what they need.

3. **A rule enters only with a test.** Added S255. A rule that cannot be
   failed is a preference, and preferences do not belong in a harness. Every
   rule names what would count as breaking it in terms someone else could
   check: a count, a file, a printed line, a named artefact. Where a rule can
   only be honoured or not honoured according to how it feels from the
   inside, it is not a rule; it is written somewhere else or not written at
   all.

   **The evidence, S254.** Nine lines in the operating instructions were
   found to be phrased so a future Claude could comply with every one of them
   while doing exactly the wrong thing. "Stuck" was the sharpest: it had no
   definition, so it meant whatever the moment made convenient. Each of the
   nine was given a test in the same pass, and the instructions got shorter.

   This part is an entry condition on rules, not a rule about messages, so it
   does not breach part 2; and it makes rules harder to add rather than
   easier, so it does not breach part 1.

**Rule 7 survives this** because it governs conduct, not shape: it says do
the work rather than narrate it. Its DID line is retired as a mandatory
field under part 2, and what remains is the substance, which is that a
change is reported only once it is made and verified.

## LAYER 2: THE MECHANISMS

Chat has no hooks: unlike Code, nothing can intercept its actions from
outside. So its mechanisms are checks that produce printed evidence rather
than assurances, in the shape the vault orphan check proved at S243 (215
notes checked, 2 orphans found, 0 after repair). A count can be read and
disbelieved; an assurance cannot.

The mechanisms are the fourteen steps of the `session-close` skill: the
five-step open and the nine-step close, each step producing its own printed
count, rolled into the two status lines. Rule 7 has no mechanism of its own,
by design. Its substance, that a change is reported only once it is made and
verified, is carried by Rule 3's read-back: the returned diff is the printed
artefact, and it lands inside the turn rather than at the session's edges,
which is where intention-versus-execution drift happens. The DID line that
formerly carried this was retired at S253 under Rule 8 part 2, because it
governed the shape of every message. The ones doing reconciliation work,
mapped to the drifts they catch:

## LAYER 3: THE INDEPENDENT EVALUATOR

The builder and the grader must never be the same mind. For Chat, the fresh
evaluator is structural: **the next session's Claude is a different instance
with no memory of this one, and it grades the previous close at every open.**
Folded into the open's Steps 1 and 2 (tightened V1.8): read the disposition
lines written onto the files the previous session archived and check they
describe work the board actually shows, run the report-against-theme
comparison (a hard stop since V1.9), and verify one handover number against
the thing it describes.
The evaluator now grades durable artefacts rather than the previous close's
own claims about itself. A close that reported falsely is caught by a
different mind within one session, and the finding is named to Kain in the
opening message.

Kain's own check stays what it is everywhere else: reading the two lines. He
never audits the close and never needs to.

## CHANGES

Changes to this harness are made only by Chat with Kain's approval, versioned
inside this document, and delivered whole. A failure found in use is never
closed by a patch in conversation: it is closed in the document, in the
session it is found.

**How it is closed is decided, never assumed.** A new rule is one option and
it is not the default. Rule 8 governs: a rule enters only as another leaves,
only with a test, and never to govern the shape of a message. Removing a
rule, correcting one that already exists, tightening a mechanism, or fixing
the thing a rule was compensating for are all closures, and the first three
cost nothing to carry. Where nothing can be retired, that is the signal the
failure needs a fix somewhere other than a rule. A version that only adds is
refused.

This document lives at the channel folder root beside `000__THE_HARNESS.md`
and the Cowork Production Harness's pointer, and is never mirrored.
