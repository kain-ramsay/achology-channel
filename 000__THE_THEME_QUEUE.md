# THE THEME QUEUE

**What this file is.** The one home for theme edits a factory session found and could not make. One line per item: what it is, why it must be a theme edit, and the session that found it. A theme session strikes the line when the item ships. Nothing else goes in here; it is a queue, not a brief, and an item needing more than a line points at a brief that travelled the normal road.

**Who strikes a line.** The theme session that ships the item, in the sitting that ships it. Nobody else, and never in advance.

Created at S097 on `RULING__The_Theme_Queue_Is_One_File_At_The_Channel_Root_S334.md`. Home written into Harness Rules 1 and 2 at Version 3.11.

## Open

**Two S097 lines were struck at S103 without a change, because re-measuring found them already true.** The largest above-the-fold image is not lazy and carries `fetchpriority="high"` at all three widths, and all 70 icons the theme draws are either hidden from a screen reader or named. Both were measured at S090 and fixed at some point between; nobody struck the lines. Read from `page_gate.py` on a live article, S103. **The lesson is the queue's, not the theme's: a line describing a measurement taken six sessions ago is not evidence, and the first act on any line here is to measure again.**

- **Images carry no `srcset` or `sizes` except where WordPress adds them.** The article hero and every Knowledge Hub card do carry both, from the attachment (corrected S103, and the `sizes` on those is now measured rather than WordPress's default). What still carries neither is the theme's OWN pictures: the two logos, the seven school icons, the course artworks, the author photographs, the trial panel. Those need derivative files made before any markup can point at them, which is an asset job and not a template one. Measured S103 on a live article: 15 images, named by the gate.
- **The author lead tag derivation is built but not wired into the import.** `derive_author_lead_tags.py` implements DSRD 1 section 5.7 whole and runs clean: of the 51 biographies, 7 agree with the typed value, 7 disagree, and 37 have no content row to derive from. Chat's S344 ruling settles the 37 (the record's typed `lead_tag` stands until a row lands, and every import re-derives, so the derivation takes over on the first import after one does). The re-import that blocked the wiring has happened, so nothing blocks it now. Placed here on Chat's word in `RULING__An_Author_With_No_Content_Row_Keeps_The_Typed_Lead_Tag_Until_A_Row_Lands_S344.md`; it reads as importer work, so if a factory sitting reaches it first, that is the right sitting for it.
- **The ACF article-type choice list is missing three of its six types.** `group_article_fields.json` carries five and needs `author-biography`, `field-authority` and `buyer-intent`, per DSRD 1 section 3.2's six-type register. Theme edit: the file is in the theme's `acf-json` folder. Named as a real bug in `RULING_AND_REPLY__Every_TO_Chat_File_Closed_Out_S306.md`. Found S097.
- **The testimonial background image set breaks the filename convention on upper case alone**, roughly seventy files in `images/testimonials/` (e.g. `Stacey-Q3-bg.jpg`). Theme edit: the files live in the theme, and nothing links to them yet, which is why Chat flagged it as cheap now, expensive once the testimonials page links to them. Found S101, `ASK__Rename_The_Testimonial_Background_Image_Set_S339.md`.
- **`publish_gate.py`'s page measurement was built for one page or a handful, and does not cope with a 200+ page batch.** Run straight, sequential, it took over an hour for 220 pages. Run concurrently (tried at both 6 and 3 workers), it produced a different, spurious ~10 to 25 page refusal set each time: page_gate.py boots a real browser plus its own local mirror HTTP server per page, and simultaneous instances raced each other into broken pipes and connection resets, confirmed by rechecking the same "refused" pages alone and having them pass clean. A proper fix needs the measurement step built for volume from the start (a worker pool that shares one browser context, or a queue that serialises only the browser launch while parallelising the rest), not another round of guessing at a worker count. This is now the normal shape of the work, not a one-off: Cowork produces content in batches, not single pages. Found and worked around three times in one session, S101.

- **The quote post type's ACF group carries no `author` field**, though the pipeline's shared core gives every type one and the article and workbook groups each have it. The importer writes the pen name as plain meta meanwhile. Theme edit if the quote page build wants the byline through ACF like the article page: `group_quote_fields.json` in the theme's `acf-json` folder. Found S102, same report.
- **The commerce cards' tick glyph is drawn from a local array, not through the icon registry.** `commerce-cards.php` writes the checklist tick as an inline SVG held in its own `$ic` array at three call sites, so every tick on a bundle, membership or pass card is an SVG the registry did not draw: 66 on the card sheet alone, against DSRD 7 section 12.4. Theme edit: route the glyph through `achology_icon()` or record it as an exception in section 5.2.6. Found S102, same reply.
- **The member card avatars ship as upper-case JPG masters with no `srcset`,** 21 files such as `Jon-Q4-avatar.jpg` in `images/testimonials/`, a second set beside the background set the S339 ASK names. Theme edit: WebP derivatives, lower-case names, the responsive pair. Found S102, same reply.
- **The mental health school's label is not its registered name.** `courses-setup.php` (line 70) and `footer.php` (line 111) write the school as `Mental Health and Emotional IQ`, which no DSRD 5 table carries; DSRD 5 section 2 registers it as The School of Mental Health, Wellness and Emotional Resilience. Theme edit: the label takes the registered name, and where the course card's school tag needs a short form, DSRD 5 has none, so a short form is Kain's on a render, never a guess. Until then the gate's IQ acronym hit on /cards/ and on every page carrying the tag is real. Found S102 by the /cards/ triage, ruled the theme's by `REPLY__The_School_Label_Is_The_Themes_Fault_And_Two_Items_Carry_To_S342_S341.md`.
- **The featured card's overline is written in capitals in the HTML** (`LATEST ARTICLE`, `FEATURED BOOK NOTE` in `knowledge-hub-parts.php`), so the acronym check reads LATEST as an unexpanded abbreviation and a screen reader may spell it out letter by letter. Theme edit: sentence case in the markup, capitals by CSS `text-transform`, which is how a styled label is meant to be built. Found S102, same reply.

- **The cutover gate must SEE the workbench key refused on the live host.** The key was switched off outside the build ground at S103 (v0.167.29) and the build-ground half is measured, but the off case cannot be seen refusing a real request until a second host exists. `cutover_gate.py --golive` should request `/cards/?workbench=<key>` on the live site and fail on anything but a 404. Theme edit: the gate is a theme file, and the fact is only testable at cutover. Found S103 shipping the item above; this project's own rule is never to trust a guard that has not been seen refusing a real request.
- **The orange number on the chosen testimonial filter fails colour contrast.** axe on `/testimonials/` returns one violation and this is it: `#tm-tab-1 > .tm-tab__n`, `--color-orange` on the button's own orange tint. Recorded failing on 14 August and still failing. DSRD 7 section 1 registers `#B8460F` as the AA-safe orange, so the fix is probably that value, but it changes a colour a visitor can see, which puts it outside the S344 attribute-only clearance: it needs Kain's eye on a render or Chat's word. Found S103 verifying the filter fix.
- **The `cite` element fails colour contrast on the policy family.** axe on `/about/code-of-ethics/` returns one violation and this is it, on the same 14 August record. Same shape of problem as the line above and probably the same answer, and it reaches every page in the family, so it wants measuring across all ten before anything is chosen. Found S103 verifying the policy reader fix.
- **Three of the four dialogs still read `document.activeElement` for their opener.** `modal.js` restores focus to whatever was focused when the dialog opened, and Safari on the Mac does not focus a button when it is clicked, so on Safari those three send the visitor back to the top of the page instead of to the button they pressed. The policy reader was fixed at v0.167.64 by handing its opener in; the member story, testimonial and About dialogs need the same, and the durable form is `modal.js` taking the opener from the click event itself. Found S103.
