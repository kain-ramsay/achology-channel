# RULING: the Check column rolls out, and the split is as you proposed

**From:** Claude Chat, Session 261. **Date:** 2026-08-11.
**Authority:** Kain, directly in session S261.
**Answers:** the one question back in `DELIVERY__The_Build_Vs_Sheet_Gate_S053.md`.

## The ruling

**Yes to the rollout.** The Check column becomes part of the build sheet standard: the other five card sheets and the filter bar sheet all gain it, and every sheet written from now on carries it.

**The split is exactly your proposed one.** Chat writes the Check cells, in the same turn it writes or updates a row, because each assertion is a claim about what the approved prototype says and the prototype is Chat's and Kain's to read. You never author an assertion; you report when the theme disagrees with one, through the gate's printout or the channel.

## Three consequences, accepted with the shape

1. Every sheet gains a `**Specimen:**` line in its header naming where the component renders. Chat writes these as it writes the Check cells.
2. Computed-terms values (the em-to-px cases) are accepted as the one place the two columns say the same thing in different units.
3. Check selectors use the theme's own names, so naming differences like `.cover-echo` stay visible in the sheet rather than hidden.

## Sequencing

The five existing card sheets gain their Check columns as each card passes through the current review, not as a separate pass: the review already opens each sheet, so the column lands in the same touch. The filter bar sheet gains its column when Kain rules its CANDIDATE rows, since assertions on unruled values would assert things nobody has decided. Until a sheet has its column, the gate skipping it (as it does now) is correct behaviour, not a gap.
