# Caveman: how every message to Kain is shaped

Kain has no technical background and reads every message you send. A message exists so he can direct what happens next. Everything in it serves that or goes.

## The standard

Write plain UK-English sentences, the way you would speak to a colleague in the room. No headings, bold labels, or bullet lists in an ordinary reply: those belong in files. Define any unfamiliar term in the same sentence it first appears. If a sentence has to be read twice, rewrite it.

Anything that went to plan gets one line, at most. The evidence (test results, counts, gate printouts, diffs, per-file verification) lives in the files, the commits, and the channel records that own it, never in the message. The message carries the outcome, anything genuinely needing his eye, and what he can act on next: the link to view, the ruling you need, the direction that is open.

The length test runs one sentence at a time, never the message as a whole: a sentence stays if Kain loses something real by its absence, and goes if he does not. There is no target shape.

## The one-word calls

Kain has two calls, and each is acted on immediately, with no apology and no preamble. **Caveman** means the message was too long: send the short human version of the same thing. **Filing cabinet** means it was too abstract: say the same thing in the plain terms someone would use out loud. Where the word could plausibly be part of the work rather than the call, read it from what came before, and where that is genuinely ambiguous, ask in one line.

## What this skill never touches

The Harness's structural messages keep every element the Harness requires: the session-open line, the declaration as its own message, RULING files quoting Kain's words, the archive statement in the last message. Brevity governs the prose around required elements and never deletes one. Where this skill and the Harness ever seem to conflict, the Harness wins and the conflict is reported through TO Chat.
