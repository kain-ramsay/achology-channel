# RULING: the book note's Amazon button reads "Read the Full Book" and loses its underline

**DOCUMENT TYPE:** ruling, filed by Claude Code, Session 114, theme session. **Date:** Monday 14 September 2026.
**Filed under Harness Rule 14.**
**Shipped:** Theme 0.396.0, deployed and verified on the live install.
**Board card:** Book note page template.

---

## 1. Kain's words

> "Yes, and please replace the CTA text with Read the Full Book"

The "yes" answers the underline: the button already carried a button's outline and padding and a link's underline at the same time, so it read as neither one thing nor the other.

## 2. What changed

The label is now **Read the Full Book**, replacing "Get this book at Amazon". The underline is off, on the button and on its hover.

**The link itself and its `rel="sponsored noopener"` are untouched.** That declaration is a disclosure obligation, not a wording choice, and it stays whatever the label says.

## 3. The label is copied, not written

His words, verbatim, from the sitting. Copying a value Kain has ruled word for word is not drafting, which stays outside Code's hands; the copied words are quoted above so Chat can check them against what he said.

**One thing for Chat to weigh, since it is a copy question and not a build one.** The old label named the destination and the new one does not, so a reader no longer learns they are leaving for Amazon until they arrive. The external-link mark beside the label still says the link leaves the site, and the `rel` still declares the relationship, so nothing legal turns on it. Raised rather than acted on: Kain gave the words plainly and they are live.

## 4. The underline was never set on the button

It comes from the article's reading wrapper, which underlines every link inside it, and that rule is the more specific one. This is the third time the same cascade trap has been recorded on this page family: the contents rail at S110, the quote page's block at S108, and now this. A block inside the writing has to out-specify the writing, and the hover has to be named alongside it or the underline returns the moment a pointer lands.

## 5. Where this leaves the sidebar sitting

This was the third and last of the three faults Code found by measuring the sidebar. The other two are done: the contents rail's mark, and the gap under the contents, which was **withdrawn rather than built** once the rule behind it was read. Both are in `RULING__The_Contents_Rail_Current_Row_Takes_An_Orange_Bar_S114.md`.

Two matters from the same sitting are still Kain's and are untouched: renaming the "Table of Contents" heading, which is copy and which Code advised against on its own because the other two headings in that column are capitals; and what happens to the Know Your Psychology graphic, which is the same full width as the cover so the eye reads them as a pair.
