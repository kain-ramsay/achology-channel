# RULING: one home for every shared feature, a site components register, and a lock (Kain, Code's founder pages sitting, S181, 26 October 2026)

**Kain's words** (in the sitting, after Code put a new "reading line" in four new forms to him for the founder pages): "I don't want you to be conjuring up features for these pages that are standalone and exist only on those pages ... You've got to treat some of these features as components ... do you also understand how inconsistent the entire website is going to become when you have different features on some pages and what you have on others? ... a permanent solution. And I don't mean a solution that's just written down in a note somewhere that you ignore ... this has something to do with site-wide components." Then, to Code's three-part answer: "Yes. Start the components register with the reading line: show me the two existing versions side by side so I pick one for the whole site."

**The fault it answers, found and measured this sitting.** The site already carries two different reading lines, each built in its own page's code: the Knowledge Hub line (knowledge-hub.css and knowledge-hub.js, THE READING PROGRESS LINE, Kain S147, made 1px at S163: a thin orange line on a grey track along the header's foot, on articles, book notes, quote pages and workbooks) and the Help answer line (help.css touch 1 and help-article.js, Kain S180: a 4px orange line along the window's top edge). Code's founder pages round would have made a third.

**The ruling, as Code put it to him and he said yes to:**
1. **One home per shared feature.** A feature used on more than one page (the reading line, list dots, link hover, the related-questions movement and their kind) is built once, in one place, and a page switches it on; a page never carries its own copy. Change the component and every page using it changes together.
2. **One register of components.** One list naming every shared feature, its signed look, where its code lives and which pages use it. A page's improvements are drawn from the register first ("this page lacks components X and Y"); a genuinely new feature is put to Kain as a component for the whole site, never for one page.
3. **A lock, not a note.** A machine check that refuses a change building a second copy of a registered feature, so the rule cannot be forgotten.

**Started this sitting:** the register's first entry, the reading line. Kain is choosing between the two existing lines on three page kinds (an article, a Help answer, the Founders' Letter) in the shared Change Viewer, previews/components-s181 (round-reading-line.js), the theme untouched. His pick will come as its own RULING, then the build of the one component that replaces both copies.
