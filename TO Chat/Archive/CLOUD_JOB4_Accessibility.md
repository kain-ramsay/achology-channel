# Job 4: read-only accessibility review of the Achology WordPress theme

Code reviewed: the `main` branch at commit `8556d96` (root PHP, JavaScript and CSS files; previews, tools and harness folders ignored). The review was done by reading the code alone. Nothing was run in a browser, with a screen reader, or against a live WordPress, so every behaviour below is worked out from the code, and where the code does not settle a point the report says "cannot tell from the code". School-colour contrast was left alone as asked.

## Summary

| Grade | Count |
|---|---|
| SERIOUS | 1 |
| SHOULD FIX | 10 |
| MINOR | 38 |
| Total | 49 |

Counts are of finding bullets below; a defect that is discussed in two places is counted once.

Headline: the theme has a good accessibility base. It has a skip link, a global visible focus ring, `prefers-reduced-motion` handling in both CSS and JavaScript, labelled form fields, descriptive `aria-label`s on icon buttons, titled video iframes, `aria-current` on breadcrumbs and pagination, and one shared modal controller (`modal.js`) that traps focus, closes on Escape, returns focus and makes the page behind inert. The one SERIOUS finding is in the mobile menu: the collapsed accordion rows are hidden only by height, so their links stay in the tab order and the screen reader tree while invisible.

Grades: **SERIOUS** = blocks or seriously misleads a group of users on a main route. **SHOULD FIX** = a real barrier or WCAG gap with a workaround, or one that depends on a data or state the code does not show. **MINOR** = small, advisory, or a near miss.

Each finding gives the file and line, one plain sentence on what is wrong, who it affects, and the safe version.

## Mobile and tablet menu, desktop menu (`header.php`, `header.js`, `header.css`)

- **SERIOUS** `header.css:599-609` (with `header.js:121-126`, `header.php:335-370`) — The collapsed mobile accordion rows (Academy, Courses, Library) are hidden only with `max-height: 0; overflow: hidden`, not `display`, `visibility`, `hidden` or `inert`, so their 6, 8 and 4 links stay focusable and readable by assistive technology while invisible, and the Tab trap counts them because it only filters out elements with no `offsetParent`. *Affects:* keyboard users, switch users and screen reader users on any screen under 880px wide (phones, tablets, narrow windows), who will tab through up to 18 invisible links with no visible focus ring and hear links under rows whose button says `aria-expanded="false"`. *Safe version:* close the row with `visibility: hidden` (transitioned together with `max-height`, as `.megamenu` already does at `header.css:177-196`) and `visibility: visible` on `.is-open`, or set the `hidden` or `inert` attribute from `header.js:150-158`.
- **SHOULD FIX** `header.js:72-81` (with `header.js:64-67`) — Pressing Escape while focus is on a link inside an open mega menu closes the menu and then moves focus to the trigger inside the same item, which fires the item's `focusin` handler and opens it again, so it takes a second Escape (pressed on the trigger) to close it. Worked out from the code, not run. *Affects:* keyboard and screen reader users on desktop widths; fails the "dismissible" part of WCAG 1.4.13. *Safe version:* set a flag (or a short timeout) in the Escape handler so the `focusin` handler ignores the focus that Escape itself moves, or move focus to the trigger before closing.
- **SHOULD FIX** `header.js:64` — The three mega menus open on keyboard focus alone, so tabbing along the bar from Academy to Membership passes through every link in the Academy and Courses panels first (7 and 9 extra tab stops) with no way to skip a panel except Escape. *Affects:* keyboard users on desktop widths. *Safe version:* open on Enter or Space (or on a separate toggle button) and leave focus-opening off; the trigger already has `aria-expanded` and `aria-controls`.
- **SHOULD FIX** `header.php:301` (with `header.js:84-131`) — The mobile menu overlay is a plain `div` with `aria-hidden` only: it is not a `<nav>` and has no label, so on small screens (where the desktop `<nav aria-label="Primary">` at `header.php:69` is hidden) there is no navigation landmark, and while the overlay is open the page behind is still available to a screen reader's virtual cursor because only the Tab key is trapped. *Affects:* screen reader users on phones and tablets. *Safe version:* wrap the list in `<nav aria-label="Primary mobile">` (or give the overlay `role="dialog" aria-modal="true" aria-label="Menu"`) and reuse `window.achologyModal` from `modal.js`, which already makes the rest of the page inert and restores focus.
- **MINOR** `header.php:72, 127, 236` — The three top-level triggers are links with `aria-haspopup="true"`, which tells a screen reader a menu (role `menu`) will open, while the panels are `role="region"` blocks of ordinary links and the keyboard model is not the ARIA menu model. *Affects:* screen reader users. *Safe version:* drop `aria-haspopup` and keep `aria-expanded` and `aria-controls`.
- **MINOR** `header.php:74, 129, 238` — The three panels are `role="region"` landmarks labelled "Academy menu", "Courses menu" and "Knowledge Hub menu", but the visible trigger says "Library" (`header.php:236`), so the label and the visible word disagree. *Affects:* speech-input and screen reader users. *Safe version:* "Library menu".
- **MINOR** `header.php:117, 184, 269` — Each panel holds an unlabelled `<aside class="nudge">` (a complementary landmark) that is exposed whenever its menu is open. *Affects:* screen reader users navigating by landmark. *Safe version:* give each an `aria-label`, or use a `div`.
- **MINOR** `header.js:89, 104` — Opening the mobile menu sets `document.body.style.overflow = 'hidden'`; if the window then grows past 880px (a tablet turned sideways) `.mobile-nav` is hidden by CSS (`header.css:517-519`) but nothing resets the overflow or `aria-expanded`, so the page cannot scroll. *Affects:* tablet and keyboard users who rotate or resize with the menu open. *Safe version:* listen for a `matchMedia('(min-width: 880px)')` change and call `closeMenu()`.
- **MINOR** `header.php:110, 121, 273, 287, 341, 376` and `footer.php:75, 84-93` — Header and footer links to the community site open a new tab (`target="_blank"`) with no spoken or visible warning, although the theme's own rule (quoted at `commerce-cards.php:325-329`, DSRD 7 section 1.0) is to add hidden "opens in a new tab" text, which `pricing-parts.php:952` and `commerce-cards.php:334` do. *Affects:* screen reader and cognitive-access users. *Safe version:* add `<span class="visually-hidden"> (opens in a new tab)</span>` or put it in the `aria-label`.
- **MINOR** `header.css:474-492, 527-537` — The menu button and its close button are 24px icons with 6px padding, so each is 36 by 36px, under 44 by 44 (but over the 24px WCAG 2.2 AA minimum). *Affects:* touch and motor-impaired users on phones. *Safe version:* `min-width: 44px; min-height: 44px`.
- **MINOR** `header.css:432-450, 14-30` — `.btn-signin` is about 36px tall (9px padding around a 12px label); the skip link is fine (shown on `:focus`, `header.css:27`). *Affects:* touch users on tablets between 880 and 1023px. *Safe version:* `min-height: 44px`.

## Modal dialogs (`modal.js` and its callers)

`modal.js` does what the task asked: Tab and Shift+Tab wrap inside the dialog (`modal.js:121-157`), Escape closes it (`modal.js:124-128`), focus returns to the opener (`modal.js:187`), and everything outside is made `inert` with `aria-hidden` restored afterwards (`modal.js:96-119`). All five callers (`about.js:357-376`, `shared-parts.js:29-67`, `testimonials.js:55-62`, `template-policy.php:463`) pass the opener and an initial-focus close button with an `aria-label`. The remaining points are small.

- **MINOR** `modal.js:121-128` with `about.js:381`, `shared-parts.js:41`, `testimonials.js:102` — The Vimeo player lives in an iframe, and key presses inside an iframe do not reach the page's `keydown` listener, so Escape probably does not close the dialog while focus is inside the video, and the user has to Tab to the Close button. Cannot tell from the code how Vimeo's own player handles Escape. *Affects:* keyboard users watching a video. *Safe version:* none needed if Vimeo passes Escape up; otherwise leave focus on the Close button at open (which the code already does) and say so in the dialog label.
- **MINOR** `modal.js:164, 182` and `header.js:89, 104` — Both scripts write `document.body.style.overflow` and clear it independently, so closing one clears the other's scroll lock. *Affects:* any user if both are open at once (not reachable today). *Safe version:* a shared counter or a class on `<html>`.
- **MINOR** `components.css:725`, `testimonials.css:107`, `policies.css:957` — The three lightbox close buttons are 40 by 40px. *Affects:* touch users. *Safe version:* 44 by 44px.
- **MINOR** `testimonials.js:109` — The poster background is set for a no-video card but never cleared on close (`onClose` clears only `innerHTML`, line 62), so a stale poster can sit behind the next dialog. *Affects:* sighted users, minor. *Safe version:* clear `style.backgroundImage` in `onClose`.

## Headings and landmarks

- **SHOULD FIX** `index.php:56` — The fallback template (search results, date, author and other archives) has no `<h1>`; the first heading is each result's `<h2>`. *Affects:* screen reader users who navigate by heading, and anyone landing on a search or archive page. *Safe version:* add an `<h1>` naming the page (for example the search term or archive title) before the loop.
- **MINOR** `learn-listing.php:151` (cards from `knowledge-hub-parts.php:329-512`) — The listing page goes straight from its `<h1>` to 24 `<h3 class="card__title">` card headings with no `<h2>` between them, skipping a level. *Affects:* screen reader users who navigate by heading level. *Safe version:* a visually hidden `<h2>` ("Articles") above the grid, or render card titles as `<h2>` on this template.
- **MINOR** `template-course.php:40` — The "not a course page" fallback prints a `<main>` with no heading. *Affects:* screen reader users on a mis-assigned page (an edge case). *Safe version:* add an `<h1>`.
- **MINOR** `footer.php:114-145` — The copyright line and the Policies navigation sit in a `div` after `</footer>` (`footer.php:112`), so they are outside the page's `contentinfo` landmark. *Affects:* screen reader users who jump to the footer landmark and miss the legal links. *Safe version:* move `.footer-sub` inside the `<footer>` element.
- **MINOR** `page-about.php:124-164` and `course-parts.php:937` — Every accordion answer panel is `role="region"` with a label, which makes 5 landmarks on the About page and 9 on a course page, more than a landmark list can usefully carry. *Affects:* screen reader users listing landmarks. *Safe version:* drop `role="region"` from the panels; the button and `aria-controls` already name them.
- **MINOR** `people-setup.php:480` — Each author card is an unlabelled `<aside>`, so a page can carry several unnamed complementary landmarks. *Affects:* screen reader users. *Safe version:* use a `div`, or label each with the author's name.
- **MINOR** `page-reviews.php:379` — The review search `<form>` has no `role="search"` or label, so it is not offered as a search landmark. *Affects:* screen reader users. *Safe version:* `role="search"` and `aria-label="Search the reviews"`.
- **MINOR** `page-about.php:264-276` (with `about.js:154-161`) — The timeline's name, dates and student count (`data-swap-name`, `data-swap-dates`, `data-stagecount`) are real text that the scroll script rewrites, but they are not hidden from assistive technology, so a screen reader meets the starting values ("Origins", "2012 to 2014", "5,000") that no longer match as the page is read; the odometer and chart beside it are correctly `aria-hidden`. Cannot tell from the code what a given reader sees at reading time. *Affects:* screen reader users. *Safe version:* `aria-hidden="true"` on `.cons-stage__left` and `.cons-count`, since the milestone list below carries the same facts.

## Images, links and link text

- **SHOULD FIX** `knowledge-hub-parts.php:335-336, 356-357, 380, 402, 442, 469, 494, 519` — Each Knowledge Hub card's title is a heading, not a link; the only links are the footer's "Read this Article →", "Read Book Note →", "Unpack this Quote →" or "Download Workbook" and a second link to the same address reading "N Minute Read", and the whole-card link is deliberately hidden (`knowledge-hub-parts.php:266`). So a listing of 24 cards gives a links list of 24 identical "Read this Article" entries plus 24 "N Minute Read" entries that do not say which article. *Affects:* screen reader and speech-input users. *Safe version:* make the `<h3>` text the link (or add a visually hidden ": {title}" to the CTA as `courses-setup.php:571` already does) and drop the duplicate "Minute Read" link from the tab order.
- **SHOULD FIX** `commerce-cards.php:333, 430, 561` — The school-bundle, Access All Areas and membership cards each carry a bare "Learn More" link, and "Enrol Now" (`commerce-cards.php:334`) has only "opens in a new tab" as hidden text, so on the Pricing page nine links read "Learn More" and nine read "Enrol Now, opens in a new tab" with no card name. *Affects:* screen reader and speech-input users. *Safe version:* add `<span class="visually-hidden"> about {card name}</span>` to each, as the course card already does.
- **MINOR** `header.php:188` — The mega-menu aside CTA is "Learn More" with its title ("Access All Courses") in a separate element. *Affects:* screen reader users. *Safe version:* "Learn more about the Access All Areas Pass".
- **MINOR** `course-parts.php:940` — "Read the full answer" repeats nine times on a course page. *Affects:* screen reader users. *Safe version:* a hidden question title after the text.
- **MINOR** `single-quote.php:698` — The download link's text is "Download" and its file name (`download="achology-quote-…"`) is not announced. *Affects:* screen reader users. *Safe version:* "Download quote card".
- **MINOR** `knowledge-hub-parts.php:597` — Numbered pagination links say "2", "3" and so on, without "Page" (the arrows do carry labels, lines 581 and 601). *Affects:* screen reader users. *Safe version:* `aria-label="Page 2"`.
- **MINOR** `template-author-profile.php:62-66, 72` — The avatar image's `alt` is the person's name and the `<h1>` directly beside it repeats the same name, so it is read twice; when no photo exists the initials ("KR") are read as letters. *Affects:* screen reader users. *Safe version:* `alt=""` on the avatar, and `aria-hidden="true"` on the initials.

Image alt text is otherwise in good order: every `<img>` in the PHP has an `alt`, decorative ones carry `alt=""` (course card heroes at `courses-setup.php:537`, mega-menu icons at `header.php:136-172`), the logo link has `aria-label="Achology home"`, and `achology_icon()` adds `aria-hidden="true"` by default (`shared-parts.php:203-206`). Cannot tell from the code: the `alt` on article and book-note card pictures comes from `get_the_post_thumbnail()` (`knowledge-hub-parts.php:302`) and so from each picture's alt field in the Media Library, which the code does not show.

## Language of parts

- **SHOULD FIX** `reviews-setup.php:701` (language read at `reviews-setup.php:663`, shown at 731-740) — Reviews written in another language (the file's own comment says 87 of the 4,516) are printed in a plain `<p class="rv-card__text">` with no `lang` attribute, so a screen reader reads them with English pronunciation (WCAG 3.1.2). ## Forms and form-like controls

The review search form is properly labelled (`page-reviews.php:383, 400, 410` use `<label for>`), the pricing plan menu has a visually hidden label (`pricing-parts.php:593`), and the course goal checkboxes sit inside `<label>` elements with a hidden `<legend>` (`template-courses.php:143-147`) and a visible focus ring on the label (`courses-directory.css:96`). The custom select in `reviews.js` follows the combobox pattern (label, `aria-expanded`, `aria-controls`, `aria-activedescendant`, `aria-selected`, Arrow, Home, End, Escape and Tab).

- **SHOULD FIX** `courses-directory.js:116-126` — The "Clear" button is created inside `sub` with `innerHTML` each time the answers change, and pressing it ticks nothing back on but re-runs `draw()`, which empties and hides `sub` (`courses-directory.js:125-126`), so the focused button disappears and keyboard focus falls back to the top of the page. *Affects:* keyboard and screen reader users. *Safe version:* after clearing, move focus to the first answer checkbox (or the results heading).
- **MINOR** `help-article.js:21-28` with `single-faq_article.php:499-506` — Pressing "Yes" or "No" disables both buttons (the pressed one had focus, so focus is lost) and reveals the thank-you line by removing `hidden`, with no live region; the two buttons are also not grouped with their question. *Affects:* keyboard users (focus drop) and screen reader users (no confirmation). *Safe version:* put `role="status"` on the thank-you paragraph, use `aria-disabled="true"` instead of `disabled` so focus stays, and give the container `role="group" aria-labelledby` pointing at the question.
- **MINOR** `shared-parts.js:79-92` — The "Copy" button's label changes to "Link copied" and back after two seconds, with no live region, so a screen reader user gets no confirmation (the article page's copy control at `knowledge-hub-parts.php:1442` does have `role="status"`). *Affects:* screen reader users. *Safe version:* add a `role="status"` span as the other control does.

## ARIA used wrongly or incompletely

- **SHOULD FIX** `pricing-parts.php:714-716` (with `pricing.js:145-159`) — The three course-category buttons carry `role="tablist"` and `role="tab"` with `aria-selected`, but there is no `tabpanel`, no `aria-controls`, no roving `tabindex` and no arrow-key handling; they actually filter one shared list, as `testimonials.js:40` (which converted its own look-alike tabs to buttons with `aria-pressed`) says is the correct treatment. *Affects:* screen reader users (told "tab 1 of 3" with nothing to match) and keyboard users (expecting arrow keys). *Safe version:* drop the `tab` roles and use `aria-pressed` buttons in a `role="group"`, as the testimonials filter does at `page-testimonials.php:152`.
- **SHOULD FIX** `template-courses.php:175` — The whole course results section (`<section id="courses-results" aria-live="polite">`) is a live region, and `courses-directory.js:106-134` rewrites its heading and re-orders up to 15 cards on every tick, so a screen reader announces the whole section on each change. *Affects:* screen reader users. *Safe version:* remove `aria-live` from the section and announce a one-line summary ("Showing 6 courses best matched to your goals") in a small `role="status"` element.
- **MINOR** `shared-parts.php:1483` — The member-answers grid is `<div aria-live="polite" aria-label="…">`; a generic `div` is not allowed a name, and nothing in it changes. *Affects:* screen reader users. *Safe version:* remove both attributes, or make it `role="group"`.
- **MINOR** `knowledge-hub-parts.php:538-541` and `learn-listing.php:170-171` — The active category pill and the active sort pill are marked only with a class (`kh-pill--active`), whereas the content-type pills in the same bar carry `aria-current="page"` (`learn-listing.php:167`). *Affects:* screen reader users. *Safe version:* `aria-current="page"` on the active pill.
- **MINOR** `page-testimonials.php:152` — `aria-controls="tm-grid"` points at an element that exists only in the JavaScript (`testimonials.js`), not in the delivered markup; a static check found it is the only dangling reference of 60 `aria-controls`, `aria-labelledby` and `aria-describedby` values. Cannot tell from the code whether the script always creates it. *Affects:* screen reader users if it does not. *Safe version:* put `id="tm-grid"` in the PHP.
- **MINOR** `reviews.js:265` — The typeahead in the custom select acts on any single-character key, including Ctrl, Cmd and Alt combinations (Ctrl+C on the focused control opens the list). *Affects:* keyboard users. *Safe version:* return early when `e.ctrlKey || e.metaKey || e.altKey`.

## Focus styles

A global rule at `base.css:988-992` draws a 2px orange ring offset 3px on every `:focus-visible` element, so no control is left without one. Controls that draw their own ring (cards at `cards.css:75-78`, checkbox cards at `courses-directory.css:96`, the floating bar in white at `courses-directory.css:114`, the custom select at `reviews.css`) are consistent with it. The only `outline: none` rules are `base.css:996` (mouse focus only, behind `:not(:focus-visible)`) and `cards.css:79` (the card-level `:focus-within` ring replaces it).

- **MINOR** `base.css:988-992` — The ring colour `#ED6922` is 3.16:1 on white (the file's own measurement at `header.css:436-443`) but about 2.9:1 on the off-white page background `#F3F4F4` (`base.css:117`), under the 3:1 that WCAG 1.4.11 asks of a focus indicator. This is the brand orange, not a school colour. *Affects:* low-vision keyboard users on off-white sections. *Safe version:* use `--color-orange-link` (`#B8460F`, 5.36:1 on white per `header.css:443`) for the ring on light backgrounds.
- **MINOR** `cards.css:75-80` — On clickable cards the footer link's own outline is removed and the whole card is ringed instead, so the ring does not show which of the card's two links has focus. *Affects:* low-vision keyboard users. *Safe version:* keep the card ring and add a visible change (underline) on `.card__footer-cta:focus-visible`.

## Reduced motion

The global reset at `base.css:971-981` sets near-zero animation and transition durations, one iteration and `scroll-behavior: auto` under `prefers-reduced-motion: reduce`, which covers every transition in every stylesheet (including the menus, cards and the global-impact and footer keyframes). The JavaScript checks the preference where it drives motion: smooth scrolling at `about.js:272` and `reviews.js:308`, the count-up and timeline at `about.js:11, 73`, `course.js:26`, `knowledge-hub.js:307`, `book-note.js:47`, `testimonials.js:14`. Videos start only after a click. No finding.

- **MINOR** `about.js:230-254` — The About timeline is driven by scroll position (a pinned frame whose track moves with the scroll and redraws the chart), and under reduced motion it still moves as the page scrolls; it is user-controlled movement, not an animation, so this is advisory only. *Affects:* people with vestibular disorders. *Safe version:* under `reduced`, take the existing flat layout (`about.js:199-200`) so the timeline reads as a plain list.
