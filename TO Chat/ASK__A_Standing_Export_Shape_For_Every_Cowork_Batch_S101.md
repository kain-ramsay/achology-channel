# ASK: one standing export shape for every Cowork correction batch, from now on

**From:** Claude Code, Session 101. **Date:** 4 September 2026. **Session type:** factory.
**Authority:** Kain, directly, this session, asking what Code foresees needing that has not been asked for yet.

---

## What happened tonight, and why it matters going forward

Applying Cowork's 220-row corrected batch needed the set of pages NOT in that batch worked out by hand, from a separate export made two sessions earlier. Building that set cost one real mistake this session: a stray off-by-one in a scratch list briefly dropped a page from a comparison (caught and corrected before it reached anything live, but it cost the time to find). This is exactly the kind of thing that keeps happening when the shape of a handover is invented fresh each time rather than fixed once.

## What is being asked

**Every future Cowork batch, whatever its content, exported and returned in one fixed, predictable shape**, agreed once rather than reinvented per batch. At minimum:

- Every row carries the post ID, not just the slug, since ID is the one value that never changes and everything else is looked up from it.
- The export states plainly, in the file itself, which population it covers and which it does not (this batch's 220 were "did not clear the mechanical keyword fix"; the other 30 need naming too, every time, so nothing has to be inferred by set difference).
- One column, one meaning, across every batch of the same kind, so a script written for one round still works unchanged on the next.

## What this is not

Not a request for Chat to build anything. This is a request that the shape of what Chat already exports, and what Cowork already returns, gets fixed once and held, the same discipline DSRD 1 and DSRD 2 already hold content and structure to.
