## 2. What is approved

The author's name, drawn as a plate, standing in the slot the photograph uses. It takes the photograph's box exactly: the 240 column, 4:5, the site's one image corner and one image shadow from the S113 rulings, and the same credit line under the same faint hairline. The credit reads "Achology" because the artwork is the theme's own.

Every approved value is in `BUILD_SHEET__bn-author-mark.md`, written this session into the Book Note Page folder in the Knowledge Hub Design Prototypes. That is the Rule 14 fold-back's sheet half, and it names which values were ruled by eye and which were measured off the deployed page.

## 3. The part Chat should carry into the DSRD word for word

**It is not a drawn likeness and it must never be turned into one.** Chat's own S358 disposition on the sourcing report is what settles this: a stylised version of a photograph is a derivative of that photograph, so tracing the picture we may not publish produces nothing we may publish. There is no photograph behind this component and no face in it.

An invented face would be worse than the gap it fills: a picture of somebody who does not exist, printed beside a real person's name, on the page that tells a reader where that person is coming from. That sentence is in the component's own comment block and in its build sheet, because this is the kind of rule a later session undoes by accident while trying to be helpful.

## 4. One thing Kain was shown that is not built, and it is a question for him

He was told, in the header of the sitting he approved, that the colour comes from the section the note lives in, so a Mental Wellness note would draw blue and a Life Coaching note terracotta.

**That mapping does not exist.** There is no route anywhere in this project from a Knowledge Hub category to a school colour, and the two sets are not the same seven: the Hub has seven categories and the schools are a different seven. Inventing one would be taking a design decision that is his.

So every mark draws the one pair he approved, read as the two school tokens rather than retyped, and the component's comment and its build sheet both say plainly that this is a gap and not a choice. **His ruling on it changes two token names and nothing else.**

This is the only thing outstanding on the component, and it blocks nothing: the marks are live and correct today.

## 5. The fold-back, and the half of it that is not done

Rule 14 asks for the approved state exported into the component's design folder as the prototype's next version, and the build sheet updated to match.

**The sheet is written.** The prototype export is not: the Book Note Page folder holds one whole-page prototype, `Book_Note_Page_S250_FINAL.html`, and the mark appears inside the author section of a real note rather than as a component that can be exported on its own. Rather than guess at what the next version of that page prototype should contain, this is named here as owed. **If Chat rules that the whole-page prototype is re-exported at the next book note ruling rather than for this one, that closes it; if not, say so and it is done in the next theme session.**
