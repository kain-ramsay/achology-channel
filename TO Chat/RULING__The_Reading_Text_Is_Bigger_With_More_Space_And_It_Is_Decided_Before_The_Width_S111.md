## 1. The ruling on the reading text

**Kain's words:** *"Yes, lets settle the text first - i think the Bigger text, more space option is good"*.

The option he chose, rendered on `/help/achology-basics-and-identity/what-is-achology/`: **the body text moves from 16px to 18px, and its line height from 1.6 to 1.75.**

Both values are already in use on this site and neither is new. **18px is a step on the nine-step scale** (DSRD 7 section 3.0). **1.75 is the line height the article and book note bodies already run** (DSRD 7 section 3.2's Article Body row, measured on both rendered pages this session). So the help answer was the page out of step, and this ruling brings the three approved pages onto one reading rhythm at a larger size.

**What it reaches.** The body role, everywhere, not the help page alone. A ruling is a rule rather than a fact about one page. **Nothing is swept yet**, on Kain's own constraint at the open of this sitting: nothing moves until he has ruled on the whole reference page.

## 2. The ruling on the order, which is the more important of the two

**Kain stopped the sitting at the first decision and said the order was wrong.** His words: *"what we haven't done is we haven't amended fonts... I don't want to be in a position where we're gonna have to come back and then rechange the container width once we've changed the font size."*

**He is right, and so was the record.** How many letters land on a line is set by the column width and the text size together. Ruling a width first and then raising the size sends the width straight back for re-ruling. **`REVIEW__Codes_Type_Roles_And_Vertical_Rhythm_Proposal_Read_With_Nine_Additions_S356` section 1 already said this in Chat's own words:** the reading width is a property of the body role, a character count per line "from which the reading column's pixel width is derived". The sentence was in the tray and the sitting was built the other way round.

**So the standing order is: the body role first, the reading width derived from it.** Carried into DSRD 7 section 4.1's measure rule, which already names the thing to measure and should now also name what decides it.

## 3. One finding that reversed the premise it was raised under

Kain brought two screenshots, a Udemy help article and one of ours, on the reading that our column was much narrower than other sites'. **Counted off those two pictures, and confirmed against this session's own measurement of the built page: Udemy's help body runs about 98 letters a line. Ours runs about 120.** Ours is the longer line, not the shorter one.

**Ours reads narrower at the top of the page only because a figure floats inside the first paragraph** and pushes the words in; below the figure the lines run the full column. What Udemy does differently is set smaller text, which is how a wide column still lands at 98.

Recorded because the same comparison will be made again, and because it changes what the reading-width decision is actually about: not catching up with wider sites, but choosing what a comfortable line is at the size Kain has now ruled.
