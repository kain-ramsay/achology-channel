## The ruling

**The two session types stay, and they are a discipline about what a sitting is for rather than a lock. Where Kain rules a change in a sitting, that sitting makes it and lands it, whichever type it is.**

## What this settles, and it settles both faults at once

**Fault one needed no wall built.** The harness says H2 refuses a factory declaration naming a theme file. H2 does not, tested deliberately at S097 rather than assumed. The answer is not to build the check: it is to correct the text, because the check turns out never to have been wanted. **A document describing a wall that does not exist is the more dangerous half of that pair**, because a reader trusts it, and the fix is one edit rather than one build.

**Fault two dissolves.** Rule 12 and H5 could not both be satisfied once a theme file had been edited in a factory session, and the only exit the harness allowed was reverting Kain's own fix. Read as a habit, H5's demand is simply right: a change set lands, in whatever sitting made it.

## What Chat changes in the harness, proposed rather than written

Four places, and **no rule is added**:

1. **Rule 1**, the two session types paragraph: the closing test loses the sentence *"a Rule 2 declaration in a factory session naming a theme file is refused by H2."* What stays is the habit: a theme sitting builds the theme, a factory sitting clears the factory, and a backlog item needing theme work goes to the theme queue **rather than being taken on speculatively**.
2. **Rule 2**: *"A declaration in a factory session that names a theme file is refused (S333): the item goes to the theme queue"* becomes that same habit rather than a refusal.
3. **Rule 12**: *"Only a theme session deploys ... whatever it finds"* gains its exception. A factory session lands the change set it has legitimately made. What Rule 12 actually protects is unchanged and is worth stating plainly in its place: nobody hand-carries a theme to the server, and a change set always lands in the sitting that made it.
4. **The record obligation, which is the whole price of the loosening.** A theme edit made in a factory session names Kain's ruling that authorised it, in the session report and in the change set's commit. **Without his word in the sitting, the item goes to the theme queue exactly as now.**

**The growth governor is satisfied:** three rules are loosened and one obligation is sharpened. Nothing is added.

## What does not change, said plainly so this is not read wider than it is

The split itself stands and earns its keep: it is why the theme gets sittings that do nothing else. **This is not a licence for a factory session to pick up theme work on its own judgement.** It is a licence for Kain to be answered when he is looking at the page. Absent his word in the sitting, `000__THE_THEME_QUEUE.md` is still the route, and it now exists.
