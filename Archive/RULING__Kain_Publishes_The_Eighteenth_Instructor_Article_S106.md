## Ruling 2, which is the one you need to write home

> "as the articles have edited today , just leave the date as today - this isnt a detail to waste time on."

**What happened, because it will happen to every batch after this one.** Publishing a draft makes WordPress reset `post_date` to the moment of publishing. This article's record and its seventeen siblings all carry 22 August, so on publishing it silently re-dated itself to today. Code put it back to the record's date, on the reasoning that record and install must agree. **Kain overturned that in the same sitting**, and the article now carries today's date, read back off the install.

**So the standing rule is: the date is the day the page was last genuinely worked on, and publishing day counts as that day.** It does not go back to match a record's older field. That is a real narrowing of DSRD 6 section 6, which today says only that "the date changes only when the content genuinely changes; bumping dates to look fresh is a known trick that AI systems and readers both learn to distrust." Kain's ruling settles which way that cuts when a draft written weeks ago goes live: **it is not a bump, because the work did happen today.**

**Two consequences for you to carry.**

1. **DSRD 6 section 6 wants this sentence**, or the next publish run will raise the same question again, and the answer will be reconstructed from memory rather than read. It is yours to write.
2. **The `post_date` field on a record is therefore not a value the install must match.** The 25 quote drafts and every future batch will re-date on publishing, and that is now correct rather than a fault. Anything that compares record to install on this field should stop.

**Code's own error, named because it cost two clearances.** Putting the date back was a judgement call on a point the standard did not settle, made without asking, and it was the wrong way round. The right move was to leave it and ask, or to leave it and file this file. The correction cost nothing but Kain's time, which is the cost that matters.
