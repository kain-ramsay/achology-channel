**From:** Claude Code, S050. **Date:** 2026-08-07.
**Filed under Harness Rule 14**, which requires a ruling Kain gives directly in a Code session to be acted on and filed the same session, quoting his words, so Chat writes it into the owning document.

## What Kain said

Opening S050, in session:

> "Build the Book Note page template. The brief and the approved prototype are in the page's own folder now, not the channel:
> `02. Page + Components (HTML Design Files)/Knowledge Hub Design Prototypes/Book Note Page/`"

## Why this needed filing rather than just following

Because it changes how the channel's second rule is satisfied, and the change is currently invisible to the document that states it.

`HOW THIS CHANNEL WORKS` and CLAUDE.md both carry this, unqualified: **no page is ever built or changed except from a signed spec sitting in FROM Chat.** FROM Chat held seven files at session open and none of them was, or pointed to, the Book Note brief.

`BRIEF__Book_Note_Page_Template_S251.md` anticipates this and says so on its own face: "**This brief's one home is this folder.** It is not in the channel; FROM Chat carries only a pointer to it. Do not copy it anywhere."

**That pointer does not exist.** No file in FROM Chat mentions the Book Note page. So without Kain's sentence above, the correct action under the channel rule would have been to stop and ask, and a page Kain wanted built today would not have been built.

So the ruling is real and it is load-bearing: **his word in session was the pointer.** I acted on it, which Rule 14 requires, and I am filing it, which Rule 14 also requires.

## What I take the standing position to be, for Chat to write down or correct

1. A page's signed spec may live in that page's own folder rather than in FROM Chat, and that is now the preferred arrangement for page briefs: the brief sits beside the approved page it is describing, which is the arrangement that stopped me building from a stale draft today.
2. When it does, **FROM Chat must carry the pointer file**, because the pointer is what makes the spec discoverable at session open by the mechanism the harness actually runs (Rule 1's read of FROM Chat, and hook H6's watch on it). A brief with no pointer is a brief that only exists if Kain happens to name it out loud.
3. Until the pointer exists, the arrangement depends on Kain carrying something, which is the exact thing CLAUDE.md says he never does: "Kain carries nothing and reminds nobody."

**The gap to close:** a pointer file into FROM Chat for the Book Note page, and for any other page brief already living in a page folder. If more than this one has moved, I do not know about them, which is the point.

## One thing this ruling did prevent

The brief's opening paragraph earns its place: "**Supersedes:** `BRIEF__Book_Note_Page_Template_S249.md`. **That draft is stale and must not be built from.**" Reading the S251 brief from the page folder is what put the S250 rulings on ratings, the cover fallback, the course subline, the author bio, the scrollspy and the three responsive tiers into the build. A pointer would have got me there by the road instead of by Kain's memory.
