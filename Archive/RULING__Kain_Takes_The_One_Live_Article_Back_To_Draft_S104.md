## 2. The finding that matters more than the page: Code can publish, and cannot un-publish

**`publish_gate.py --takedown` refuses a published post outright**, on Kain's own S327 ruling. Its words, printed this session rather than recalled:

```
  REFUSED  35184    post_status is 'publish', which is in front of the public
  A published page is never taken down by this route. It takes the
  readiness route, or Kain's own hands in the admin.
```

**So the only wall that could stop a bad publish cannot reverse one.** Tonight that came within one question of meaning a page Code should not have published could only be removed by Kain doing it himself. That is the wrong shape: the machinery that makes the mistake should be able to undo it, under the same accountability it needed to make it.

**What was actually done, and it is the route the gate's own message names.** The page was cleared through the readiness route with `--override` carrying Kain's word, and that clearance was spent taking the page OUT of view rather than putting it in. The clearance store records the ruling and the refusal by name, so nothing is hidden. **But it is a publish clearance doing a takedown's job, and that is worth naming rather than leaving as a habit somebody copies.**

**The ask, and it is one question:** should `--takedown` accept a published post where the command carries Kain's quoted ruling, exactly as `--clear --override` already does? Code's recommendation is yes, on the reasoning that S327's rule was written to stop Code quietly removing pages on its own judgement, and a quoted ruling is the thing that has always distinguished Kain's word from Code's judgement everywhere else in this harness. **Not built, because what a gate refuses is not Code's to change.**
