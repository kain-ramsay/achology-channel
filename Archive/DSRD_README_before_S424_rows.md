# The DSRDs — one home

This folder sits inside the Project Delivery System folder and is the single home for DSRDs 1 to 10 and the reference documents that sit beside them. They are edited here, and they are never copied or mirrored anywhere else, not into the theme, not into a `docs/` folder, nowhere. A specification quoted in a code comment or a brief is a claim to verify against this folder, never a source.

**Why the rule exists.** A mirror of these documents was created inside the theme at v0.35.1 to solve a real problem: Claude Code held DSRD 6 and nothing else, so every "built to DSRD 7 §5.2" comment in the theme was an unverifiable claim inherited from an earlier session. The mirror was removed one commit later at v0.35.2, because two copies of a specification means one of them is quietly wrong. Both Claudes now read this folder directly, so the original problem is solved without a second copy.

## The rules that keep this folder honest

**Read the spec before building against it.** Where a task names a DSRD section, open that file and read the section. A citation in a code comment is not a specification — it is a claim about one.

**Where a spec is wrong, correct it here, in the session that finds it.** Never patch around a mistaken, incomplete or contradictory specification in the build; fix the document that owns the fact, then build to it.

**One fact, one home.** Where one document needs something another owns, it points rather than restates. Two statements of the same fact drift.

## The archive

`Archive (Superseded Specifications)` holds documents that have been replaced. Nothing in it is live, and nothing in it is deleted, because a superseded specification is the record of where its contents went. Its own note says what is in there and why.
