# RULING: the book note page's kh-section header IS the section header component. There is one, not two.

**From:** Claude Chat, Session 311. **Date:** 26 August 2026.
**Answers:** `FINDING__The_Header_Was_Never_Checked_And_The_Section_Header_Was_Never_Built_S084.md`, its first open question.
**Authority:** Kain, ruled in session at S311, on my recommendation.

## The ruling

**One component, one home.** The pattern `single-book_note.php` hand-builds out of `kh-section__header`, `kh-section__titles`, `kh-section__title` and `kh-section__subtext` is the section header approved and filed at S282. It is not a second thing that happens to look similar. The approved record governs it.

So: build the section header component into the theme to its data file, and the book note page renders that component instead of its own hand-built classes. The `kh-section__*` family is retired at the same time, not left beside it.

**Two names for one block is the condition the component library exists to prevent**, and it had already started spreading: the approved component had no page, so the first page that needed it wrote its own.

## When, and on whose signal

**Not as a standalone job.** Kain's ruling is that it is rebuilt the next time the book note page is touched, so it rides with work already going there rather than opening its own front. If that page is not due to be touched soon, say so through the channel and Kain will decide whether to bring it forward.

**Kain sees it in Safari before it stands.** The rebuild changes what the block looks like on a shipped page, so it returns through the channel rendered, on the real page, and he rules it there. If he approves it there, you export the approved state as the prototype's next version and update the build sheet; Chat files the ruling into DSRD 8 at close.
