## Full context (standalone)

The Notion board is the project's live worklist, and it is only as true as its match to what actually exists in the theme and on the site. Chat is running a board consolidation and needs the build's side of the truth from the one who holds it. The page_gate map you already have queued covers the built pages' readiness; this snapshot covers everything around the pages, so together the two let Chat verify every Website Rebuild card against reality rather than memory.

## The work

Produce ONE report through TO Chat, alongside or straight after the page_gate map, with five sections:

1. **Theme and template inventory.** The current theme version, and per page type: built, partially built, or absent. Include templates that exist but serve nothing, and page types that fall through to a fallback (as the tag URLs falling through to index.php did).
2. **WordPress back-end state.** Which custom post types, taxonomies, and field groups actually exist and are populated, versus empty or absent: the honest state the Build WP Back End card should be checked against.
3. **Deployed but untracked.** Anything live on the build site (a page, a feature, a behaviour, an asset pipeline) that you know exists but that you believe no board card or spec tracks.
4. **Claims versus build.** Anything you know a card, spec, or handover claims that the build contradicts: state the claim, state the reality, judge nothing.
5. **Your view of next.** From where you sit, the shortest honest list of what genuinely stands between the current build and the Phase A publishes, and any dependency you can see that Chat's side may not.

Name the file plainly, e.g. `REPORT__Build_State_Snapshot.md`. Where you are not certain of something, mark it uncertain rather than smoothing it; an honest gap beats a confident guess.

## Shelf life, stated up front

This snapshot feeds one board reconciliation pass and then archives. It is not a living document and will not be maintained; the board stays the living thing. So write it for one reader doing one verification pass, not for posterity.

## Order

After the page_gate map, since you will be in exactly this territory producing it. It must not delay the audio regeneration, the keyword score run, the link ceiling check, or the map itself.
