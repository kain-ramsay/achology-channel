## 1. The ruling, in his own words

> "i'd rather we clear our backlog before taking on new work, hense the reason why Chat isn't sending you too much today!"

## 2. What it settles

**Existing open instructions are worked before new ones are written.** Kain names it as already shaping what Chat sends, so this records a practice he has started rather than imposing a new one.

**For Chat:** fewer new briefs while the inbox is deep. The measurement, taken from the channel this session by `derived_backlog.py`: **56 open instructions**, of which 13 wait on Kain, 3 on Chat, 1 on Cowork, and the rest are Code's.

**For Code:** the next session is spent on what needs nobody. Eighteen of the open instructions need nothing from Kain, Chat or Cowork. The order Kain approved:

1. **The four straight reads that are holding other people up.** The eighteen book slugs Cowork waits on, the three S320 course page questions, the confirmed book note column list Chat asked for, and the S079 captures in a form Chat can open.
2. **Six small closers, each one closing a whole instruction.** The folder map generator pointed at the project root; `content_gate.py` taught to read `section_count`; the redirect workbook's governance sentence; the machine-two ssh key file; Kit's plugin installed with both checks run; the fourteen testimonial videos whitelisted.
3. **One large piece: the image and icon machinery**, both halves. Chosen because Kain's own image standards rest on it and its cost multiplies with every image produced before it exists.

**Expected: twelve to fourteen of the sixteen closed.** Stated as a range rather than a promise of all sixteen, because a half finished list handed back is the thing this ruling exists to stop.

## 3. What is deliberately not in that session

**The seven policy pages moving from 620 to 880.** Code's own S085 ruling requires Kain to see one policy page rendered at 880 before all seven move, so it needs his eye and is not solo work.

## 4. What Chat may find useful

The backlog is now derived rather than written: `harness/derived_backlog.py` reads every WAITS line off the channel at the moment it is asked, groups by who the line says holds it, and runs the stale disposition check over the same files so a line the evidence disputes is marked rather than repeated. **It replaces the hand written S088 list**, which was four sessions stale on the day it was written and is what handed Kain a sitting he had already given.

**One weakness in it, named rather than hidden:** a WAITS clause naming nobody falls to Code by default, so a chrome sitting whose clause reads only "sittings 2, 3 and 4" lands on Code's list rather than Kain's. The default is that way round on purpose, because over counting Code's own work is safer than parking work on somebody who never agreed to it, but the grouping needs another pass before it is read unchecked.
