## What it is for, in one paragraph

Kain said at S088: **"I seem to be kinda repeating myself quite frequently, and having to redo tasks I have already delivered."** He was right, and there is a proven instance. He approved the site-wide header in Safari at S080. Five sessions later Code read its own stale disposition line, told him all four chrome sittings were still open, and asked him to book one he had already given. He caught it.

## The mechanism, because the fix follows from it

Code writes a disposition line on each inbox file saying what it waits on, writes it once, and then trusts it. When the work closes, that line is corrected only if the file happens to be opened again. A closed job can therefore sit in the channel wearing an open label indefinitely, and any list built from those labels hands it back to Kain.

**H8 guards the absence of a line, never its truth.** It refuses a close while a file carries no disposition. A line that is present and wrong passes it silently. That is the hole.

## What is commissioned

**A check that re-reads every WAITS line against its own evidence rather than trusting it.**

Most WAITS lines name something checkable, and that is what makes this cheap:

- A line waiting on a **Safari sitting** for a component is checked against whether that component's folder holds a signed prototype and a data file. The header's did, five sessions ago.
- A line waiting on a **file arriving** is checked against whether that file now exists.
- A line waiting on **a run** is checked against whether its report exists in TO Chat or the Archive.

Where the evidence says the work is done, the check says so loudly and names the file, so the line is corrected and the instruction archived rather than quietly carried for another five sessions. Where a line names something no machine can test, it says that too, so the size of what it cannot see is visible rather than assumed away, which is the standard the other gates in this harness already hold themselves to.

**It is proved the way every gate here is proved: by showing it refusing.** The acceptance run puts the header's own S080 case through it and shows it caught, because that is the case that cost Kain a repeated request.

## Two more holes the same fault exposed, which are not commissioned here

**A closing ruling should archive the commission it closes.** The header's approval was filed, dispositioned by Chat and archived, while the commission it closed stayed live in Code's inbox with an open label.

**The backlog should be derived from the channel at every open, never written once.** The one produced at S088 is the first, and a hand-written list goes stale exactly the way the lines it reads did.

Both touch how the channel is worked rather than how the theme is built, so Chat's view is welcome before either is built.
