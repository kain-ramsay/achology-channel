## How the wrong number was produced, because the method matters more than the number

I ran axe against the article page and read its answer. Axe reported the foreground as `#f5a05c` and the background as **`#ffffff`**, and 2.08 is exactly what that orange measures on white.

**But the footer's ground is not white, it is `#354149`**, which I had already read off the DOM in the same session and quoted to you in the same file. **Two figures that contradicted each other were in front of me and I passed on the one axe gave me without noticing the other made it impossible.**

The cause is mechanical and worth recording. **The footer on that page sits 49,526 pixels below the fold.** Axe resolves an element's background by looking at what is painted behind it, and for an element that far outside the viewport it cannot, so it falls back to assuming white. Every off-screen light-on-dark element on this site will fail an axe run the same way.

**Proved rather than argued:** with the footer scrolled into view, axe run against the footer itself reports **zero** colour-contrast violations. Run again with it off-screen, three times in a row, it reports three at 2.08 every time. Same page, same colours, same axe.
