# RULING: while a stream ruling is in force, the session open reads only that stream's files

**DOCUMENT TYPE:** ruling, given by Kain directly in a Claude Code session. **Session:** Code S073. **Date:** 20 August 2026.
**Filed the same session it was given, per Harness Rule 14.**
**Amends in practice:** Harness Rule 1, which currently requires every file in FROM Chat to be read at every session open.

---

## The ruling, in Kain's word

The question put to him, in full:

> While a stream ruling is in force, may I read the harness plus only the FROM Chat files inside that stream, and list the rest by name without opening them?

His answer:

> "yes"

## What it changes

**Rule 1 currently says:** "First acts, before any work: read every file in FROM Chat, and read this document, all fourteen rules."

**From now on, while a stream ruling is in force,** the session open reads the harness in full, reads the FROM Chat files that sit inside the live stream, and lists every other file by name without opening it. The first message still states that both the channel and the harness have been read, and it now also names the stream and the count of files left unopened.

**Where no stream ruling is in force, nothing changes.** Rule 1 applies in full, as written.

## Why he ruled it, measured rather than argued

At the S073 open, FROM Chat held 27 files totalling 137KB. **Three of them, 14KB, were inside the live video stream.** The other 123KB was component and chrome work parked under Kain's own video-only ruling, and it had been read in full at every session open since that ruling was given.

The cost is real and it repeats. The read buys nothing while the parked work cannot be acted on, and it consumes the context that the actual work needs. Kain raised it himself by asking how the video updates continue at maximum context saving.

## What it does not weaken

**Nothing is skipped silently.** Every unopened file is named in the opening message, so a file that should have been read is visible as an omission rather than invisible.

**A file that arrives inside the live stream is read in full, always.** The scoping is by stream, not by size or by convenience.

**The moment a stream ruling lifts, the whole backlog is read.** Parked work is deferred, never dropped, and Rule 13's archiving obligation is untouched: a consumed instruction still leaves the folder.

## What Chat may want to do with this

The wording belongs in the harness, which is Chat's document and never Code's. This file is the record; the amendment to Rule 1 is Chat's to write.

**One thing worth considering while that is written.** A `Parked` subfolder inside FROM Chat would make the same saving structurally rather than by rule, and it would survive anybody forgetting the rule. Code has not created one, since the folder's shape is Chat's.
