## Gap 10: the help section's 250 keywords now reach the register

**Closed, and it was worth closing.** The uniqueness check could not see a single one of the 250 keywords the help section has claimed for years, because those pages live on the install and not under Content Records. A new piece could have taken a keyword an existing help article already holds and nothing anywhere would have said so.

**They are not written out as 250 record files, deliberately.** A record is the thing a piece is drafted from, and these are edited on the install; 250 files that looked like records, that nobody drafts from, and that drift the moment anyone edits a page would be a worse fault than the gap. So `export_help_keywords.py` writes one claims file from the install, and `build_keyword_register.py` folds in any `*__CLAIMS.csv` beside it, in the register's own columns, clashing against the records exactly as records clash with each other.

One reading decision: Rank Math stores a comma separated list and **only the first entry is taken as a claim**. The rest are secondary keywords, and a secondary keyword is not a promise that no other page may take it, so treating one as a claim would invent clashes that are not there.

**The register now carries 454 rows from five record folders and one claims file. 250 of them are the help section. There is no clash anywhere**, and all nineteen instructor-article rows still carry the slugs your batch table names.
